# ACCRL 翻訳ガイドライン

## 概要

AI Collective Creativity Respect License (ACCRL) の国際的な普及のため、各言語への翻訳を進めています。翻訳にあたっては、単なる言語変換ではなく、各文化圏での理解しやすさと法的適用可能性を重視します。

## 翻訳の原則

### 1. 意図の正確な伝達
- 直訳にこだわらず、概念の本質を伝える
- 文化的文脈を考慮した表現の選択
- 法的正確性と読みやすさのバランス

### 2. 重要概念の扱い

| 日本語 | 英語 | 説明 |
|--------|------|------|
| 著作者人格権 | Moral Rights / Creator's Moral Rights | 法域により異なる概念 |
| 見えない貢献者 | Invisible Contributors | ACCRLの中核概念 |
| 創作的人格 | Creative Personality | 創作者の思想・美学・意図の総体 |
| 透明性記録 | Transparency Record | AI協働プロセスの記録 |
| 協働 | Collaboration | 単なる使用ではなく協力関係 |

### 3. 文化的配慮

#### 人格権が弱い法域（例：米国）向け
- 概念の丁寧な説明を追加
- 実例を多く含める
- 契約的アプローチとしての側面を強調

#### 人格権が強い法域（例：欧州）向け
- 既存の法的概念との関連性を明示
- ベルヌ条約との整合性を強調
- 既存の権利を拡張する概念として位置づけ

## 翻訳への貢献方法

### 新規翻訳の開始
1. Issue で翻訳開始を宣言
2. 該当言語のディレクトリを作成
3. LICENSE-v0.1-PROTOTYPE.md から翻訳開始
4. Pull Request で提出

### 既存翻訳の改善
1. 改善点を Issue で議論
2. 修正案を Pull Request で提出
3. ネイティブスピーカーのレビューを受ける

### 翻訳で注意すべき表現

1. **"shall" vs "should"**
   - shall: 義務（法的拘束力あり）
   - should: 推奨（道義的責任）

2. **"must" vs "may"**
   - must: 必須要件
   - may: 選択的/許可

3. **受動態 vs 能動態**
   - 英語: 受動態を多用（客観性）
   - 日本語: 能動態も可（親しみやすさ）
