# 透明性記録について

このディレクトリには、ACCRLプロジェクトにおけるすべての重要な議論と決定過程の記録を保管しています。

## なぜ透明性記録が重要なのか

1. **理念の実践** - ACCRLが提唱する「透明性」を自ら実践
2. **進化の追跡** - プロジェクトがどのように発展してきたかを可視化
3. **参加の促進** - 新規参加者が文脈を理解できる
4. **信頼の構築** - 意思決定プロセスの公開による信頼性向上

## 記録の種類

### 1. 創世記録（Genesis）
- ファイル: `2025-07-05-genesis.md`
- 内容: プロジェクトの誕生時の対話
- 意義: 根本理念がどのように生まれたかの記録

### 2. 改善議論（Improvements）
- 形式: `YYYY-MM-DD-topic.md`
- 内容: 重要な改善や変更に関する議論
- 例: `2025-07-15-improvements.md`

### 3. コミュニティ対話（Community）
- 形式: `YYYY-MM-DD-community-topic.md`
- 内容: コミュニティメンバーとの重要な議論
- 今後作成予定

### 4. リブート記録（Reboot）
- ファイル: `2026-08-12-reboot.md`
- 内容: 初版から約13ヶ月後の再検討（スタンスの確定、非強制軸の言語化、AI協働の誤りの記録を含む）

### 5. 設計決定記録（Design Decisions）
- ファイル: `2026-08-12-vessel-decision.md`
- 内容: 「器はライセンス、実態は誓約」の決定（open-questions Q2・Q3 の決着）

## 記録の読み方

各記録には以下の情報が含まれます：
- **日付と参加者** - いつ、誰との議論か
- **議題** - 何について話し合ったか
- **人間の創作的判断** - 人間が下した重要な決定
- **AIの協働内容** - AIがどのように貢献したか
- **結論と今後** - 何が決まり、次に何をするか

## 新しい記録の作成方法

重要な議論や決定があった場合は、`template.md`を使用して記録を作成してください。

### 記録作成の基準
- プロジェクトの方向性に関わる議論
- 新しい概念や機能の追加
- 重要な問題の解決
- コミュニティからの重要なフィードバック

## 多言語対応

重要な記録については、要約版を多言語で提供することを推奨します：
- 英語要約: `YYYY-MM-DD-topic-summary-en.md`
- その他言語: 必要に応じて追加

## 透明性レベル

すべての記録には透明性レベルを明記します：
- レベル1: 概要のみ
- レベル2: 主要な議論ポイント
- レベル3: 詳細な議論内容
- レベル4: 完全な対話記録

## アーカイブポリシー

- すべての記録は永続的に保持
- 修正は新しいバージョンとして追加
- 削除は原則として行わない
