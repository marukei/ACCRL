## 決定1: 本プロジェクトへの v0.3 の適用に、GitHub アカウント名で署名する

**人間創作者の判断**：

**条文上の確認**（AI による整理）：

- v0.3 は署名者に本名を求めていない。第7条1号の帰属は「創作者の氏名**または創作者が指定する名称**」であり、名称の指定は創作者に委ねられている

- したがって、人間創作者が指定する名称として GitHub アカウント名を用いることは、v0.3 の規定と矛盾しない

**反映**：

- `LICENSE` の採用者・創作者を「marukei（https://github.com/marukei）」とした
- 署名は、付録Aの雛形（テンプレート）ではなく、本プロジェクトの `LICENSE` そのものに対して行う。条文を書いたプロジェクトが、その条文を自らに適用し、人間が一人称で誓約する——自己言及的な適用がここで完結する

### 査読の結果と統合

- 意味・主体・否定の範囲を取り違えた箇所は、2体とも0件だった
- 英語の法文としての読まれ方の問題が3件見つかり、すべて直した
  - 第11条2項の "The parties try to…"：契約当事者の定型語であり、三人称の単純現在は義務規定として読まれる
  - 付録Bの "is not to be misrepresented"：禁止形になっている
  - 付録Bの理由欄：「判定者を置いた」と逆の意味に読める
- 用語の揺れを直した
  - 「約束」が1箇所だけ promise になっていた
  - 「許諾」の名詞が grant と license で揺れていた
  - 「理念」が principle と philosophy に分かれていた
- その他、細部の欠落（「背景の**違い**」）、見出しの逆読み（Reservation for AI Training）、契約の語彙（accept）を直した。統合した修正は計37箇所
- 査読で見つかった用語集の抜け（理念、内在的批判、著作者、応じる、判定者、誓約者、表記の方針）を用語集に追加した
- 作業の過程で、`README.md` と `FAQ.md` の英語節が現行の v0.3 を "a covenant in substance" と説明していることに気づいた。v0.3 は付録Bで、covenant と読まれることを除くと明記している。そのため、現行版を説明する2箇所だけを pledge に改めた。2026-08-12 の決定を記した履歴の記述は、当時の人間創作者の言葉として残した

### 採らなかった提案

- **Non-Viral → Non-Propagating**: ACCRL は規範の「伝播（propagation）」を本丸の問い（open-questions Q1）としており、同じ語で「伝播しない」と書くと混乱するため採らなかった
- **第10条3項を一人称にする**: 原文は開示の主体を書いていない。訳文で主体を補わず、受動態を保った

### 人間創作者の確認を待つ点

1. **正文**: 訳文の冒頭に「日本語が原文であり、齟齬があれば日本語が優先する」と書いた。第14条で準拠法を置く以上、どの言語の条文が正文かは英語の読者が必ず問うため、暫定で置いたもの
2. **「ライセンスフリーも立派なライセンスである」**（性格1、2026-08-12 の人間創作者の言葉）: 英語の -free は「〜が無い」を意味し、"license-free … is a license" は自己矛盾文になる。そのため「何も求めないライセンスも立派なライセンスである」（"Even a license that asks nothing of anyone is a perfectly good license."）と解釈して訳した。意図と合っているかの確認を要する
3. **強制（coercion）と執行（enforcement）**: 第3条の見出し "Undertaking Not to Coerce" などについて、査読では「実際の内容は執行しないことなので enforce のほうが法的に正確」という異論があった。設計軸の標語との対応を優先して coercion のままにしている
4. **第11条2項**: 原文「当事者は誠実な対話を試み…努力をする」は記述文である。英語で義務規定に読まれることを避けるため、"Both sides are invited to…"（呼びかけ）とした。原文にない「呼びかけ」の語を補っている
5. **第1条2号**「その判断に責任を持つ人間」: 「その判断」を「本ライセンスを採用する判断」と解釈して訳した
6. 用語集の「暫定」の各項

### 翻訳の範囲を超えるが、記録しておく指摘

- 第2.2条の留保は許諾範囲の限定であるため、英米法の読者からは、機能的には条件と同じ（範囲外の利用は侵害になる）と指摘されうる（査読A、確信度は中）。原文の第2.2条2項は「法的効果は法律による」と正直に書いている。open-questions への追記の候補とする
- 原文・訳文とも、許諾に「永続的（perpetual）」の語がない。これは原文の問題であり、翻訳では補っていない

### 手順

| 段階 | 担当 | 条件 |
|---|---|---|
| 逆翻訳（英→日） | サブエージェント（Fable 5.1） | **読んでよいのは英訳だけ**とした。原文・用語集・CLAUDE.md は読ませていない。元の日本語を推測して「復元」させないためである。下訳（Sonnet）と同じモデルの癖で原文に戻ってしまうことを避けるため、別のモデルにした |

### 結果

- 往復後も、規範の強さと主体を決める骨格は第1〜16条・付録A〜Cの全体で保たれていた。骨格とは、採用者だけが拘束されること、第II部は契約ではなく義務を課さないこと、許諾は撤回不能・無条件・非終了であること、人格権の意図的な沈黙、判定者を置かないこと、である
- **(A) 英訳が原因**のずれとして、要修正1件と提案6件が挙がった。Claude Code は次のように扱った
  - 第2.2条1項「法律上の原状に戻す」：英訳の "as it would otherwise stand" は、何がなければの状態かが定まらず、逆の意味にも読める。修正した
  - 性格2「強制しないという約束」：enforce は目的語を要する他動詞で、目的語がないと第3条より広く読める。"not to enforce the pledges in Part II" と補った
  - 第3条1項：「解釈されない」を "is to be construed" とすると、英語では禁止の指示に読まれる。"constitutes" に改めた
  - 第6条3号の "them"：「作品」を受けるようにも読めるため、"their creators" とした
  - 第8.4条：「同等の敬意」の構文を整えた
  - 第9.1条：コロンの後に説明文が割り込む構造を直した。この崩れは、最初の統合で Claude Code 自身が持ち込んだものだった
  - **採らなかった提案**：第11条2項を "We invite both sides" とする案。採用者（創作者）自身が対話の一方の当事者であり、「私たちが両者に呼びかける」は筋が通らない。人間創作者が了承した受動の形を維持した
- **(C) 逆翻訳の揺れ**：10件前後。訳語の違いにとどまる

### (B) 原文が原因の論点（条文改訂の候補。英訳は原文に忠実なので翻訳では直さない）

往復翻訳は、翻訳の検証だけでなく、原文そのものの曖昧さを浮かび上がらせた。いずれも人間創作者の判断を要する。

〔2026-09-30 追記〕人間創作者の承認を得て、13件を仕分けた。1・2・5・6・7・10・12・13 は文言の不備として公開前に v0.3 の中で直した。3・4・11 は open-questions の Q6〜Q8 に、8・9 は KNOWN_ISSUES に登録した（[記録](./2026-09-30-v0.3-wording-corrections.md)）。その後 Q6〜Q8 は、原点に照らして細部の論点と判断し、open-questions から移した（[原点への回帰](./2026-09-30-return-to-origin.md)）。

1. **第3条・性格2**：「強制しない」の目的語がない。原文で「誓約を」と明記するかどうか
2. **第4条**：見出しは「本ライセンスが及ばない範囲」だが、末段は「第II部は規範として及ぶ」と言う。及ばないのは第I部である
3. **第6条1号と第10条**：第6条1号は、AI が関与したときに人間の判断まで明らかにすると誓う。一方、第10条のレベル1は「AIを使用した事実」だけである
4. **第8条**：見出しは「敬意継承の**誓約**」だが、内容（8.1）は**呼びかけ**である。第II部冒頭の区分と食い違う
5. **第8.4条**：「同等の敬意」の比較の対象が本文にない（v0.2 の名残。付録Bにだけ出てくる）
6. **第10条1項**：「推奨される透明性のレベル」の中で、レベル3だけが「（推奨）」とされている
7. **第10条3項**：誰が開示するのかが書かれていない
8. **第12条**：採用者でない創作者まで免責している。ただし法的に拘束されるのは採用者だけである
9. **第14条**：第II部が契約でないという性質決定そのものを、どの法が判断するのか
10. **第16条**：版を「適用する」のは採用者だけのはずだが、利用者も挙げている
11. **付録A**：SPDX の一行が一人称の誓約の表明になるとされている。識別子を書いたのが AI エージェントや採用者以外の寄与者である場合、誓約の帰属が曖昧になる
12. **付録B**：「covenant と読まれる余地を除く」は断定が強い。否認を明記しても効果は保証されず、「余地を小さくする」程度が正確
13. **付録Aの英語の雛形 "We acknowledge the countless creators…"**：日本語の雛形は「敬意を表します」だが、英語の雛形には respect の語がない。原文の一部であるため、英訳では変えていない

第6条4号（coercion）と第11条4項（enforcement）は、原文ではどちらも「強制の道具」で、どちらも第3条を指す。訳し分けは用語集の方針（第II部の誓約は広い語）に沿っているが、英語だけを読むと別々の約束に見える。
