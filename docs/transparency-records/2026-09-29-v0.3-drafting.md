## 4フェーズサイクルでの整理

### 発散（Divergence）

Claude Code が4方向の調査を並行して行った。

1. AI・著作権の法的動向（米・EU・英・日、人格権・声・肖像）
2. LLM生成コードとOSSのポリシー
3. 非強制・非感染のライセンス設計の先行例
4. 機械可読な意思表示と来歴の標準

あわせて Claude Code 自身が v0.2 と周辺文書を点検した。調査環境では、GitHub 以外の一次資料ドメインのほとんどが遮断されていたため、検証水準を項目ごとに明記した（[sources.md](../sources.md)「2026-09 追補」）。

### 生成（Generation）

調査3（先行例の設計分析）から、v0.2 に対する**内在的な批判**が得られた。いずれも外形的な評価（使われていない・法的に不利）ではなく、思想の不明瞭さ・内部矛盾の指摘である。

1. **人格権軸と非強制軸の混同**: design-axis §2.1 は人格権を「譲渡も強制もできない権利」と書いたが、人格権は譲渡できないだけで、他者に対しては強制力を持つ（日本法では差止めまで可能）
2. **誓約の主体の不在**: 「利用者は…誓約する」という三人称は、同意していない人に誓約を帰属させていた。非拘束の先例（Contributor Covenant、DCO、SemVer）は一人称で誓うか、契約でないことを明示的に否認している
3. **「covenant」の二重の意味**: 英米法の covenant は強制可能な約束を意味する。v0.2 は第II部を契約上の約束と読まれる余地を残していた
4. **第5.2条が出発点の危惧を要請していた**: 派生物を ACCRL で公開するよう求めることは、「被許諾者の地位を広げること」を求める形になっていた
5. **目的と手段の緊張**: 前文の「エコシステムを守る責任」は成果を志向しており、非強制という手段と整合しなかった

Claude Code 自身の点検からは、FAQ の記述（「契約法上有効」「執行力はコミュニティの採用から生まれる」「普遍的な概念を明確にしているだけ」）が現在の設計と矛盾していることと、CLAUDE.md の記述が古いこと（原則2が旧称、v0.1 を「法的拘束力のある本体」と記述）が見つかった。

これらに応えて v0.3 を起草した。v0.2 からの変更点は [v0.3 付録B](../../LICENSE-v0.3-PROTOTYPE.md)（承認前の草案では付録C）に、先行例との対応は [non-coercive-design-2026.md](../legal-analysis/non-coercive-design-2026.md) にまとめた。

### 確認（Verification）

- 外部環境の記録に**訂正が3点**必要になった。訂正は [2026-review.md](../2026-review.md) の本文中に〔2026-09 訂正〕として見える形で入れ、本文そのものは 2026-08-12 時点の記録として残した
  1. 「主要AI企業が RSL **等**の宣言を尊重すると正式表明した事実は確認されていない」は範囲が広すぎた。EU の汎用AI行動規範で、主要なモデル提供者は robots.txt に従うことを署名文書で約束している。確認されていないのは、帰属・対価といった**ライセンス条件**の尊重である
  2. Linux カーネルの `Assisted-by:` の書式は v7.3 以降 `Assisted-by: LLM [tools]` に簡素化され、モデル名を記録しなくなった
  3. Cloudflare の 2026-09-15 の既定変更の対象は、公式文面では「新規にオンボードするドメイン」に限られる
- 条文の条番号の飛び（第5条の次が第8条）を起草後に見つけ、振り直した
- design-axis §2.1 と open-questions Q3 の混同は、削除せずに〔2026-09 訂正〕として訂正を見える形で残した

### 収束（Convergence）

v0.3 の起草を通じて、非強制の軸が二つの文に集約された。

> **法的に拘束されるのは、自ら採用した者だけである。**
> **規範は著作権に依存しない。**

一つ目は、初版からの危惧（被許諾者の網が広がること）への最も正確な応答である。ライセンスという器を使う以上、利用者は被許諾者になる。しかしその地位にはいかなる義務も伴わず、義務を負うのは自ら誓った採用者だけになる。

二つ目は、初版の出発点にあった問い——「MIT や Apache は AI との協働作品に適用できないのではないか」——への一つの答えになった。ライセンスは著作権のない部分で空振りするが、非強制の規範は空振りしない。これは設計の目的ではなかったが、非強制の軸から自然に導かれた。

## 人間の判断を要する点（未決）

Claude Code は次の点について判断を下していない。

1. **v0.3 の設計そのものの承認**。特に「法的に拘束されるのは採用者だけ」という整理が、2026-08-12 の「器はライセンス、実態は誓約」の決定の意図と一致しているか
2. **人格権の不行使宣言の既定**（[open-questions.md](../open-questions.md) Q5）。v0.3 は「既定では付さない」としたが、これは人格権軸と非強制軸のどちらを優先するかという、思想の根幹に関わる判断である
3. **自己適用ライセンス（LICENSE）の版**。本リポジトリの LICENSE は v0.1 のままにしてある。v0.3 の論理では、採用は誓約であり、誓約できるのは人間だけである。したがって、LICENSE を v0.3 に切り替えるかどうかは、AI ではなく人間創作者が決めることである
